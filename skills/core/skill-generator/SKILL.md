# Skill Generator

1. Define concrete request examples, non-goals, decisions, data, risk, and accountable owner.
2. Classify the need as skill, workflow, reasoning pack, knowledge, engine, schema, policy, or adapter. Do not create a skill when another component fits.
3. Initialize the skill with the repository skill initializer; write concise trigger metadata and a companion `skill.yaml` contract.
4. Add only necessary references, source map, evals, synthetic fixtures, tests, capability entry, and workflow links. Use deterministic code for repeatable math or matching.
5. Validate contracts, links, token budget, overlap, sources, and adversarial behavior before proposing maturity.

Refuse to copy restricted material, invent policy, or grant approval authority. Preserve human gates and progressive disclosure.
